# RK3588（DC-A588）固件调试记录

> 日期：2026-09-25
> 目标：给原厂 GB-RK3588 Ubuntu 24.04 GNOME 镜像开启"上电自启 ADB"，烧录到 DC-A588 板 eMMC，打通调试通道

---

## 一、镜像结构（分析结论）

`GB-RK3588-ubuntu24.04-...-gnome-v01-ALL-A-CM-EN.img`（14GB）不是普通磁盘镜像：

- **RKFW 烧录容器**：sector 0 = RKFW 头（含组件表、版本日期），内嵌 RKAF 升级包
- **RKAF 包**位于 `0x77226`（1.1GB），文件表每项 0x70 字节（name/path/offset/size），9 个文件：parameter、MiniLoaderAll、uboot、misc、boot、userdata、oem、rootfs
- **整个文件就是一个 ext4 文件系统**（卷名 `linuxroot`，13.01GiB），起点 `0x43B4226`（**非 512 对齐**），RKAF 里的 rootfs.img（1GB）只是它的前 1GB 切片
- 备份超级块按 sparse_super 规则排布（128MiB 间隔），可用于定位 fs 起点
- 解析工具：`rkunpack`/`afptool`（rk2918_tools，GitHub 被墙时可用 `apt-get source rkflashtool` 或 Debian 源 `deb.debian.org` 下 orig 包）

## 二、ADB 默认关闭的根因

两处厂商 bug 叠加：

1. `/etc/init.d/.usb_config` 内容是一行 `' usb_adb_en'`（**带前导空格**），`usbdevice` 脚本用 `case "$line" in usb_adb_en)` 精确匹配 → 永不命中 → `ADB_EN=off` → adbd 不启动
2. `/etc/rc.local` 第 14 行 `echo host > .../otg_mode` 会在开机末尾把 OTG 切到主机模式，把 ADB gadget 顶掉（注释却写着 open otg to adb）

**正确改法**（仅此两处，其余保持原厂）：

```
/etc/init.d/.usb_config  → 精确一行：usb_adb_en
/etc/rc.local            → host 改为 peripheral
```

## 三、踩坑点（简记）

| 坑 | 现象 | 结论 |
|---|---|---|
| SoCToolKit v2.96 整包签名校验 | 改任何字节都"固件摘要检查失败"，无法加载 | 摘要校验无私钥无法绕过；**用经典 `upgrade_tool.exe UF`（MarkToolbox 自带，不校验摘要）** |
| 移植飞牛 FNNAS 启动链（GPT+FIT） | 烧完掉 MASKROM / 心跳灯不亮（内核没起来） | 缺 `0x40` 扇区 idblock；且 booti/FIT 与原厂 U-Boot 匹配 uncertain。放弃此路线 |
| 飞牛工具裸写要求 512 对齐 | `Image size ... is not 512-byte aligned` | 补齐到 512 倍数（零填充即可） |
| A-to-A 线（公对公） | 板子掉 MASKROM | 那个 USB-A 口兼作救砖下载口，A对A 触发下载模式；**调试用 Type-C 口（或支持设备模式的口）+ A对C 线** |
| 最终镜像忘改 root 密码 | SSH 时 rk3588 密码不对 | 最小改动版只改 ADB 两文件，密码仍是原厂未知值；**烧后 adb 下 `usermod -p '<sha512哈希>' root` 修改**（chpasswd 被 pwquality 拒，<8 位） |
| dtb 说 A 口全是 host | 实测某 A 口 + A对C 线 adb 正常 | 以实测为准 |

## 四、正确流程（最终成功路径）

### 1. 最小改动镜像制作（WSL 内）

```bash
# 提取整个 ext4（起点 0x43B4226 = 70992422 字节，别记错）
dd if=原厂.img of=fs.img iflag=skip_bytes,count_bytes bs=16M skip=70992422 count=13974487076

# 离线改两个文件（loop 挂载 /mnt/d 会只读，用 debugfs）
printf 'usb_adb_en\n' > uc.txt
debugfs -w -R 'rm /etc/init.d/.usb_config'  fs.img
debugfs -w -R 'write uc.txt /etc/init.d/.usb_config' fs.img
debugfs -R 'dump /etc/rc.local rcl' fs.img
sed 's/^echo  host/echo peripheral/' rcl > rcl.new
debugfs -w -R 'rm /etc/rc.local' fs.img
debugfs -w -R 'write rcl.new /etc/rc.local' fs.img
debugfs -w -R 'sif /etc/rc.local mode 0100755' fs.img

# 回填 + 补齐 512 对齐
dd if=fs.img of=minimal.img iflag=fullblock oflag=seek_bytes conv=notrunc bs=16M seek=70992422
python3 -c "import os;f=open('minimal.img','ab');f.truncate((os.path.getsize('minimal.img')+511)//512*512)"

# 验证：与原厂对比 [0, 67.7MB) 应逐字节相同；SFI 解析应通过
upgrade_tool.exe SFI minimal.img    # Type:Update Firmware / Sign:false
```

### 2. 烧录（板子进 MASKROM 后）

```bat
:: MarkToolbox 自带：C:\ProgramData\MarkToolbox\bin\upgrade_tool.exe
upgrade_tool.exe LD                                    :: 确认设备 Mode=Maskrom (VID_2207&PID_350B)
upgrade_tool.exe UF D:\...\GB-RK3588-gnome-minimal-adb-on.img
:: 约 6~7 分钟（37MB/s），写完自动重启
```

### 3. 烧后验证与配置

```bat
adb devices                 :: 应列出设备
adb shell                   :: 直接 root
```

```bash
# 板子上（adb shell / ssh）：
# root 密码改为 rk3588（chpasswd 会被 pwquality 拒，用 usermod 直写哈希）
usermod -p "$(openssl passwd -6 rk3588)" root   # PC 上生成哈希再粘进 adb shell

# 以太网静态 IP（持久化，直连 PC/笔记本用）
cat > /etc/netplan/99-eth-dbg.yaml <<'EOF'
network:
  version: 2
  ethernets:
    alleth:
      match: {name: "e*"}
      addresses: [192.168.10.2/24]
      dhcp4: true
      optional: true
      renderer: networkd
EOF
chmod 600 /etc/netplan/99-eth-dbg.yaml && netplan apply
```

PC/笔记本侧：网卡设 `192.168.10.1 / 255.255.255.0`，**网关和 DNS 留空** → `ssh root@192.168.10.2`。

## 七、启动介质选择（2026-09-26 定案）

**日常用 eMMC 启动，不做 TF 卡启动。**

| 维度 | 板载 eMMC 64G | TF 卡 |
|---|---|---|
| 速度 | eMMC 5.1 HS400 档，顺序 ~150–300MB/s，4K 随机快 | UHS-I 上限 104MB/s；4K 随机常 5–20MB/s，GNOME/apt/日志写入明显肉 |
| 可靠性 | BGA 焊死无触点，门口/闸机环境抗振 | 弹片触点，振动/温变有接触不良风险 |
| 掉电 | 一般优于廉价卡 | 廉价卡无掉电保护，断电易整盘文件系统损坏 |
| 寿命 | 64G 应付日志写入足够 | 普通 TLC 卡被日志写死快，需买 High Endurance 级 |
| 恢复 | maskrom + `upgrade_tool.exe UF`（本文已验证） | 拔卡重刷即可 |
| 灵活性 | 换系统要重烧 | 拔插即换、多系统方便 |

TF 卡唯一真实优势是"折腾/换系统快"，本板已有验证过的 maskrom 救砖链路，该优势基本被抵消。

- TF 槽留空或只放数据卡；**勿长期插"可启动"的 TF 卡**（BROM 介质探测顺序以板厂 strapping 为准，插了可启动卡可能改变实际启动介质）。
- eMMC 整卡备份（可选）：板子进 MASKROM → 按工具报出的容量分段 `upgrade_tool.exe rd <beginLBA> <sectorCount> <file>` 读回再拼接（64GB ≈ 125000000 个 512B 扇区；空块多，img 可压缩）。不备份也能复原：重刷基础镜像 + 重打 §二两处修复 + 重设 root 密码/netplan，备份只是省这 20 分钟。


## 八、LPRNet 识别全链路实测与推理口径更正（2026-09-26）

本节更正 §六/AGENTS 早期记录中的两条推理口径，并记录边缘识别服务的实测结果。

### 1. 推理口径（实测定案，推翻旧记录）

| 项 | 旧记录（错/过时） | 实测定案 |
|---|---|---|
| `init_runtime()` | "必须 `target='rk3588'`" | **必须不带 target**。带 target 会走 adb/代理模式，直接报 `Unsupported run platform: Linux aarch64`（lite2 2.3.2 实测） |
| 输入格式 | "NHWC"（未写 dtype/归一化） | **NHWC uint8 `(1,24,94,3)`**，transpose 成 NCHW 或预归一化 float 都解错（"晋A"/"黑E" 之类） |
| 转换 config 键名 | `input_mean/input_std` | toolkit2 2.3.2 用 **`mean_values/std_values`**，旧键名直接 ValueError |
| 模型/运行时版本 | — | 模型 2.3.2 vs librknnrt 2.1.0 打 `RKNN Model version ... not match` **WARN 可忽略**，推理结果正确 |
| 归一化 | 手动 `-127.5 × 1/128` | 转换时 `mean/std=127.5` 烘进模型，**运行时自动做**，喂 0-255 uint8 即可 |

## 九、MP157↔RK3588 以太网排障实录（2026-09-26）

> 板间链路验收当天连环踩坑的全记录，结论先行：**现网 = MP157 板载网口(eth0) ↔ RK3588 eth0 直连（都是千兆）；RTL8152 USB 网卡方案因载波反复抖动退役；RK 侧 NetworkManager 必须钉死 unmanaged。**

### 坑 1：RTL8152 USB 网卡载波抖动（退役）

- 现场唯一一根网线先走 "MP157 的 RTL8152 USB 网卡(eth1, r8152) ↔ RK eth0"，曾稳定 10 分钟（ping 2.8ms / 中继 / park_ui 收流全过），随后 dmesg 里 `carrier off/on` 每 1~4 秒一轮，链路彻底不可用的状态与可用状态交替出现。
- 该 dongle 百兆（`PRODUCT=bda/8152`），无法解释后来 RK 侧协商出的 1Gbps——说明线上对端被换过/换线时认错了口，排查时 **"协商速率 vs 对端能力"是利器**。
- 结论：USB 百兆小网卡不适合当常驻板间链路；MP157 **板载 RJ45（stmmac, RGMII, 千兆）直连 RK eth0** 后稳定（Link Up 1Gbps/Full，再无抖动）。

### 坑 2：NetworkManager 抢 eth0（根因级）

症状链：netplan 静态 10.2 时有时无；手动 `ip addr add` 两分钟后消失；`networkctl` 显示 "configured/degraded" 却只有 IPv6LL。

- 根因：GNOME 桌面残留的 NM 配置文件（"有线连接 1/2"、"eth0"）把 eth0 抢走跑 DHCP（对端无 DHCP 服务器→永远"正在获取 IP"），networkd 的 netplan 配置被架空；**删除 NM 活动连接的瞬间 NM 还会把设备上的 IPv4 地址冲掉**（avahi `Withdrawing address record for 192.168.10.2` 实锤）。
- 处置（已在板上生效）：
  1. `nmcli con delete` 清掉所有 eth0 的 NM 配置（有线连接 1/2、eth0）；
  2. 写 `/etc/NetworkManager/conf.d/99-eth0-unmanaged.conf`：`[keyfile]\nunmanaged-devices=interface-name:eth0`，`systemctl reload NetworkManager` → `nmcli device show eth0` 显示 `GENERAL.STATE: 10 (unmanaged)`，重启后也不复发；
  3. `networkctl reconfigure eth0` → networkd 按 netplan 应用 10.2（稳定，双向往返 0.4~0.6ms）。

### 坑 3：ssh 默认没起

- RK 镜像 ssh.service 非 enabled（`systemctl is-active ssh` = inactive）→ 已 `systemctl enable --now ssh`。

### 安全加固（同日，响应"配置有没有可能被攻击"审计）

- 审计发现：edge_hub/lpr_server 无鉴权绑 0.0.0.0（可注入伪造 K2:OK 进开闸链/偷摄像头画面）、sshd 允许 root 弱口令登录、NM 调试热点 `dcztl/12345678` 躺在配置里、adbd 仅 127.0.0.1（✓ 无问题）。
- 已修：两个服务**只绑 192.168.10.2**（`--bind`/`--host`，启动 bind 重试 2s×30）；`sshd_config.d/99-hardening.conf` = `PasswordAuthentication no`（仅密钥，三把：台式机/笔记本/MP157）；`nmcli con delete Hotspot`。
- 未修（用户决策）：MP157 root 空口令 + LAN 可达（`PermitRootLogin yes`/`PermitEmptyPasswords yes`）——出厂默认，用户明确"MP157 侧不用管"；MP157 出厂服务 mosquitto/usbipd/rpcbind 同理保留。
- 残余（物理信任模型）：板间专线明文可注入（开闸还需知道白名单车牌）；RK adb Type-C 无鉴权直给 root。
