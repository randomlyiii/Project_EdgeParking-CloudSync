# 第 5 步 · K210 ↔ Linux 通讯（预览流 + 抓拍识别）

> 步骤：5 ｜ 前置：G0（K210 到位、接线）；**与第2~4步完全独立，可并行开工** ｜ 产出：`k210_fw/` 四模块固件 + `core1_ui/k210_link/` 前端 ｜ 验收门：G5
> 架构约定（Task.md 第一节）：预览流**常开**（与推理解耦）；只有收到 Core1 的"抓拍识别"指令才执行一次 KPU 推理并回结果。
> 串口帧格式权威母本在文档 10；本文帧表为工作副本。

## 1. K210 固件（`k210_fw/`）

### P5-01 固件路线与环境 ⬜（2026-09-07 定版：CanMV MicroPython）
- **路线（已定）**：CanMV MicroPython 固件 + **CanMV IDE**（嘉楠官方）开发。四模块语义不变，落盘载体从 C 目录改为同名 .py 文件（`capture.py / preview.py / infer.py / uart_proto.py`）；boot.py→main.py 上电自启。
- 原"首选 Kendryte standalone SDK（C）"降为**备选**：仅当需要裸 KPU/极致性能时再评估（届时同步改本文与文档 10 口径）。
- 环境：CanMV IDE（USB 联机调试/上传；Windows 需装 USB 驱动）；USB CDC = REPL 115200；数据 UART 921600 起步走板级引脚（与 REPL 物理分离，不混用）。
- **验收**：CanMV IDE 联机出图、main.py 自启、协议层 PC 自检（`k210_fw/tools/selftest.py`）通过。

### P5-02 串口协议（`uart_proto/`）⬜ —— 先写协议层后接业务
```
| 帧头 0xAA 0x55 | type(1B) | seq(2B LE) | len(2B LE) | payload(len B) | CRC16(2B, 校验 type..payload) |
```
- type：`0x01` 预览 JPEG 块 ｜ `0x02` 帧尾（4B 总长 + 1B 用途：0 预览 / 1 抓拍） ｜ `0xC1` CMD_RECOGNIZE（下行） ｜ `0xC2` 识别结果 JSON ｜ `0xC3` 失败 JSON（抓拍 JPEG 走 0x01/0x02 用途=1） ｜ `0x7E` 心跳/状态 —— 帧级细节（CRC16=XMODEM / seq 计数 / ts 语义）以文档 10 与 `docs/protocols.md` 为准，本文不重复维护。
- 单帧 payload ≤1KB（实测调），长数据分块同 seq 连发。
- **验收**：PC 串口助手收发测试过（CRC/丢块/乱序处理）。

### P5-03 摄像头采集 + JPEG 编码（`capture/`）⬜
1. DVP 初始化（模块自带 OV 型传感器按型号配）；预览分辨率 320×240 或 640×480。
2. 片上 JPEG 编码器压缩，质量调到单帧 8~15KB。
3. 带宽核算：921600bps≈92KB/s → 10KB/帧 ≈ 8fps 上限；目标 **≥5fps**（KPI）。
- **验收**：JPEG 在 PC 可打开、无花屏。

### P5-04 预览流常开（`preview/`）⬜
- 主循环持续采集→编码→分块发送，**与推理状态无关永远在跑**。
- 推理期间允许预览短暂停顿（KPU 资源竞争），恢复后立即续流、seq 继续递增（Core1 靠 seq 容忍丢帧）；`0x7E` 状态帧带"识别中"位。
- **验收**：连续 10 分钟串口流稳定；触发识别前后预览自恢复。

### P5-05 指令解析 ⬜
- 收 `0xC1` → 置识别请求（识别中收到的新请求丢弃/置 busy）；回 `0x7E` 带 busy 状态。
- **验收**：发指令收到 ACK。

### P5-06 车牌识别模型（`infer/`）⬜
- **路径 A（推荐）**：MaixHub 在线训练 / 开源车牌检测+识别 kmodel，nncase 转换，KPU 加载；输出车牌串+置信度。
- **路径 B**：仅做车牌**检测**（有无车牌/框），识别交给云兜底——端侧准确率 KPI 需下调口径（文档 12 标注）。
- 约束：K210 RAM 6MB，输入 ≤320×240；输出字符集 [省份简称+字母+5 位] 映射表。
- **验收**：PC 单测——打印车牌照片，置信度合理、字符集合法。

### P5-07 结果回传 ⬜
- 成功：`0xC2` + `{"plate":"苏A12345","confidence":0.93,"ts":...}`。
- 失败/低置信：先 0x01/0x02（用途=1）连发抓拍 JPEG（供云兜底），再 `0xC3` + `{"error":"no_plate"}`。
- **验收**：一次指令恰好一次回传（成功或失败二选一，无重复）。

### P5-08 PC 直连自测钩子 ⬜
- USB-TTL 直连 PC（不依赖 A7）：脚本化——收预览流、发 0xC1、收 0xC2/C3。
- **验收**：全流程在 PC 端先闭环，再上板（避免 A7 侧问题混淆）。

## 2. Core1 前端（`core1_ui/k210_link/`）

### P5-09 串口前端 + 预览重组 ⬜
- 串口 raw 921600（设备名来自 P0-06），独立接收线程；
- 重组器：帧头/type/seq/len/CRC 校验；`0x01`+`0x02` 组完整 JPEG；seq 跳变→丢帧计数（容忍，不报错刷屏）；JPEG 完整帧队列深度 2~3（防内存膨胀，旧帧丢弃）。
- 预览超时判线：>1.5s 无帧 → 预览状态置断。
- **验收**：板上收到连续 JPEG（先落文件抽查完整性，不接 UI）。

### P5-10 识别状态机 ⬜
```
IDLE ──触发事件──► TRIGGERED ──发 0xC1──► SENT ──► WAIT(3s)
                        ▲ busy 回包则重试1次     │ 0xC2/0xC3
                        └──────────────────── RESULT / TIMEOUT
```
- **单次触发一次识别**：识别进行中再来的触发直接丢弃（与 M4/C8T6 的冷却机制双保险）。
- **验收**：连续 5 次触发，5 次识别、无并发错乱。

### P5-11 结果校验与发布接口 ⬜
- 校验：字符集合法性（省份+字母+5 位）、置信度阈值（`RECOG_CONF_TH`，初始 0.60，第7步联动云兜底）；
- 本步发布 = 写日志 + 本地暂存抓拍 JPEG（云兜底用）；**跨核 IPC 对接在第6步 P6-04**。
- **验收**：结果可查、低置信结果被标记。

### P5-12 断线重连 ⬜
- UART 读超时/连续 CRC 错 → 关重开串口 → 恢复后发状态查询请求关键帧；期间识别线置不可用。
- **验收**：拔插 K210 串口 → ≤3s 自动恢复收流。

### P5-13 预览最小显示（可选先行）⬜
- 本步验证"预览能用"即可：落文件或临时 Qt 窗口显示（正式 UI 规格见文档 11，第6步做全）。

## 避坑

- K210 与 A7 均 3.3V TTL；接线前按模块丝印确认串口脚（Maix Bit 为 A16/A17 等）。
- UART 无流控：发送靠应用层节流；Core1 重组器必须能丢帧（见 P5-09）。
- 供电不足（USB 口带不动）表现为莫名复位——用带供电 HUB 或独立 5V。
- 推理期间预览掉帧是预期行为，别当 bug 修；让 UI 显示"识别中"而不是花屏。
