# 第 2 步 · M4 ↔ 下位机 CAN 通讯（500k 双向打通）

> 步骤：2 ｜ 前置：G1（C8T6 本地功能就绪） ｜ 产出：CAN 双向互通 + `docs/protocols.md` CAN 章 ｜ 验收门：**G2（CAN 底盘闭环）**
> 两端任务都在本步：C8T6 侧接上收发，M4 侧补齐 FDCAN 配置（现在收不到任何帧）。M4 在架构中定位 = **CAN↔RPMSG 网关**，本步先做 CAN 半边，RPMSG 在第3步接上。
> 字段级帧定义的权威母本在文档 10；本步内嵌的帧表为工作副本，改协议时两处同步。

## 1. CAN 帧约定（与文档 10 同步维护）

| 方向 | ID | 数据（DLC=8，未用字节 0） | 含义 |
|---|---|---|---|
| 主→从 | 0x100 | `d[0]`：0x01 开闸 / 0x02 关闸 / 0x10 查询 | 指令 |
| 从→主 | 0x200 | `d[0]` event(0x01 遮光/0x00 恢复)、`d[1..2]` lux 大端、`d[3]` drop%、`d[4]` 状态位 | 事件上报 |
| 从→主 | 0x210 | `d[0]` 状态位（bit0 闸开 bit1 遮光中 bit2 光感故障 bit3 CAN 错误）、`d[1]` 上电秒低 8 位 | 心跳 1Hz |

- 超时约定：主端 3s 无 0x210 → 判从节点离线（第3步经 RPMSG 报给 A7）；从端不判主端。

## 2. C8T6 侧任务

### P2-01 CAN 过滤器 + Start + RX 🟨（2026-09-06 C8T6 侧已实现，待烧录联调）
> 落地偏差：C8T6 侧采用**零中断纯轮询**（`CAN_Node_Init` 过滤器+Start 于 main USER CODE 2；`CAN_Rx_Task` 10ms 轮询 FIFO0），未走下方 ActivateNotification+回调——理由与代码见 `c8t6/can.md` §5.2；下方中断写法留作指令突发时的后备。
`main.c` USER CODE 2（**调度器启动前**）：

```c
CAN_FilterTypeDef f = {0};
f.FilterIdHigh         = (0x100u << 5);   /* 标准帧 ID=0x100 */
f.FilterMaskIdHigh     = (0x7FFu << 5);   /* 精确匹配 */
f.FilterFIFOAssignment = CAN_RX_FIFO0;
f.FilterBank           = 0;
f.FilterMode           = CAN_FILTERMODE_IDMASK;
f.FilterScale          = CAN_FILTERSCALE_32BIT;
f.FilterActivation     = CAN_FILTER_ENABLE;
HAL_CAN_ConfigFilter(&hcan, &f);
HAL_CAN_Start(&hcan);
HAL_CAN_ActivateNotification(&hcan, CAN_IT_RX_FIFO0_MSG_PENDING);
```
- 回调 `HAL_CAN_RxFifo0MsgPendingCallback`（`USB_LP_CAN1_RX0_IRQHandler` CubeMX 已生成）：`HAL_CAN_GetRxMessage` 后**只置标志/写目标变量，动作放任务里**。

### P2-02 指令处理 → 道闸目标 🟨（2026-09-06 C8T6 侧已实现：逻辑闸状态+OLED 行3+状态位 bit0；SG90 硬件后加时接 `Gate_StepTo` 即可）
```c
/* 回调内（CAN_Rx_Task 消费亦可） */
if (rh.StdId == CAN_CMD_ID && rh.DLC >= 1) {
    switch (data[0]) {
    case 0x01: g_gate_ccr_target = GATE_OPEN_CCR;  break;
    case 0x02: g_gate_ccr_target = GATE_CLOSE_CCR; break;
    case 0x10: g_send_status_req = 1; break;   /* 回 0x200 带当前状态 */
    }
}
```
- 复用第1步的 `Gate_StepTo()` 缓动；OLED Line3 `Gate:OPEN/CLOSE` 跟随。
- **验收**：收到 0x100/0x01 → 舵机 90°；0x02 → 回位。

### P2-03 0x200 事件发送 🟨（2026-09-06 C8T6 侧已实现：`CAN_Node_SendEvent`，BH1750_Task 遮光边沿调用；含查询应答共用本帧）
```c
static void CAN_SendEvent(uint8_t ev, uint16_t lux, uint8_t drop)
{
    CAN_TxHeaderTypeDef th = {0};
    uint8_t d[8] = {0}; uint32_t mb;
    th.StdId = CAN_EVT_ID; th.IDE = CAN_ID_STD; th.RTR = CAN_RTR_DATA; th.DLC = 8;
    d[0] = ev; d[1] = lux >> 8; d[2] = lux & 0xFF; d[3] = drop;
    d[4] = g_status_bits;   /* bit0 闸开 bit1 遮光中 bit2 光感故障 bit3 CAN 错误（与 0x210 d[0] 同源） */
    if (HAL_CAN_AddTxMessage(&hcan, &th, d, &mb) != HAL_OK) { g_can_err++; }
}
```
- `Shade_FSM_Update` 边沿触发：`1 → ev=0x01`，`-1 → ev=0x00`；OLED Line4 闪 `EVT!` 1s。
- 邮箱满/失败计数，连续失败置 `CAN:ERR`。
- **验收**：对端（M4 或分析仪）收到且字段正确。

### P2-04 0x210 心跳 🟨（2026-09-06 C8T6 侧已实现：`CAN_Node_Poll` 内 1Hz 发送，d[0]=状态位、d[1]=上电秒低8位）
- 1Hz：`d[0]=状态位`（同帧表）；`d[1]=上电秒 & 0xFF`。
- **验收**：对端 3s 收不到 → 能判离线（配合 P2-10）。

### P2-05 OLED CAN 行启用 🟨（2026-09-06 已启用：`CAN:OK`/`CAN:EVT`(事件后闪1s)/`CAN:ERR`，见 `c8t6/can.md` §5.4）
- Line4：启动成功 `CAN:OK`；事件时闪 `EVT!`；错误 `CAN:ERR`。
- **验收**：三种状态都能观察到。

## 3. M4 侧任务

### P2-06 CubeMX FDCAN1 参数修正 🟨（2026-09-06 M4 侧已实现：fdcan.c，待烧录联调校验实际波特率）—— 本步第一优先
| 参数 | 现值 | 目标 | 说明 |
|---|---|---|---|
| NominalPrescaler | 1（≈1.25M） | **40** | 位时序自检见下 |
| Standard Filters Nbr | 0 | **≥1（4）** | 用 filter0 掩码收 0x200~0x2FF |
| RxFifo0ElmtsNbr | 0 | **16** | 已设 |
| NominalTimeSeg1/2 | — | **3 / 1** | 采样点 80%（原 2/2=60%，已改） |
| TxFifoQueueElmtsNbr | 0 | **8** | 发 0x100 走 TX FIFO，必须 >0（已改） |
| RxFifo0ElmtSize/TxElmtSize | — | Classic（8B data） | 保持 |
| FrameFormat / Mode | — | Classic / Normal | ✅ 已配 |

**位时序自检**：确认 Clock 树 FDCAN kernel mux → PLL3（默认 100MHz）。目标 500k：
`100MHz ÷ Prescaler ÷ (1+Seg1+Seg2) = 500k` → Prescaler=40 时需 **1+Seg1+Seg2 = 5**（如 Seg1=3、Seg2=1、SJW=1，采样点 80%）。以 CubeMX 底部"实际波特率"显示 ≈500.0k 为准，采样点 ≥75%。

### P2-07 队列改造：`uint32_t` → 帧结构体 ✅ 已完成（但改为"免队列"）
- **2026-09-06 决策**：M4 收路径不建接收队列——`CANRxTask` 每 10ms **轮询 FDCAN1 RX FIFO0 直接解析**（零中断，与 C8T6 从端同风格，本链路 1Hz 心跳+零星事件）。原 `CanRxQueue`(16×uint32) 已从 freertos.c 与 .ioc 移除。
- 若将来改中断驱动，再按下方帧结构体/队列实现（P2-09 中断方案）。
```c
typedef struct { uint32_t id; uint8_t dlc; uint8_t data[8]; } CanRxMsg_t;
/* 中断方案: 队列改 16 × CanRxMsg_t，同步改 osMessageQueueNew 的 item size 与消费端 */
```

### P2-09 RX 中断（推荐）或轮询 ✅ 采用轮询（2026-09-06）
- **已选轮询**：`CANRxTask` 每 10ms `HAL_FDCAN_GetRxFifoFillLevel>0 → GetRxMessage → 解析`（`can_master.c` `CAN_Master_Poll`）；未 `ActivateNotification`（NVIC 已使能 FDCAN1_IT0=3，无 IE 不触发）。
- **中断方案**留作后备（帧率增大时）：NVIC 已勾 `FDCAN1 interrupt 0`，`stm32mp1xx_it.c` 已有 `FDCAN1_IT0_IRQHandler`；

### P2-10 CANRxTask 消费与离线判定 🟨（2026-09-06 已实现，待烧录观察）
- 0x200 → 写入 `g_can_master_mon` 监视槽（last_ev/last_lux/last_drop/slave_status/ev_count），第3步 RPMSG 取走；
- 0x210 → 刷新 `last_hb_tick`、`online=1`、`hb_count`；`osKernelGetTickCount()` 差 >3000ms → `online=0`（离线标志）。
- **验收**：调试器 live watch `g_can_master_mon`——遮光时事件槽变化；拔 CAN 线 3s 内 online 置 0、插回恢复。
- ⚠️ MP1 HAL 用 `HAL_FDCAN_AddMessageToTxFifoQ` 发送（无 MP2 的 `AddTxMessage`），`CAN_Master_SendCmd` 已封装。

### P2-11 无分析仪自测手段 🟨（2026-09-06 已实现，待烧录）
- C8T6 心跳 1Hz = "总线活着"探针：M4 `g_can_master_mon.hb_count` 持续涨 ⇒ 物理层+两端波特率 OK。
- M4 侧下发指令：`CAN_Master_RequestCmd(0x01/0x02/0x10)` 或调试器写 `g_can_master_cmd_pending=1, g_can_master_cmd_value=0x01`（→ C8T6 Gate 翻转/查询应答）。**未用底板按键**（按键为 Linux input 子系统所有，其中 1 个留给 M4 尚未接，见 can.md §1 互动方案）。

### P2-16 分级联调（四步推进）⬜
1. **只测心跳**：C8T6 发 0x210，M4 live watch 收到 ⇒ 物理层+波特率 OK。
2. **事件上行**：遮光 → 0x200 → M4 事件槽变化。
3. **指令下行**：M4 发 0x100 → SG90 动作 + OLED Gate 变。此时 RPMSG 未通（第3步才接），触发手段二选一：调试器 live 改变量强制走发送函数；或用 CAN 分析仪直接发 0x100 只验 C8T6 侧响应。
4. **稳定性**：连续遮光/恢复 20 次，两端错误计数不增长（M4 `GetErrorCount`、C8T6 ESR）。
- **四步全过 = G2 达成**。

### P2-17 联调故障矩阵 ⬜

| 现象 | 检查顺序 |
|---|---|
| 完全收不到 | 两端实际波特率（CubeMX 显示值）→ H/L 反接 → 60Ω → 共地 → 过滤器 ID/掩码 → **Filter Nbr=0 / FIFO 深度=0（M4 经典坑）** |
| 时通时断 | 只挂一个终端电阻 → 杜邦线接触 → 采样点差太大 |
| 收到但字段乱 | lux 大端组装 → DLC 未按 8 → M4 `DataLength>>16` |
| 发送失败 | `AddTxMessage` 返回值 → 邮箱满未等 TxOK → 对端未 Start |
| M4 Bus_Off 挂死 | 未做恢复逻辑（第3步 P3-04 补） |

## 避坑

- 掩码 `0x7FF` 是精确匹配；将来要收 0x1xx 组指令时改 M4/C8T6 掩码放宽并同步文档。
- `HAL_FDCAN_GetRxMessage` 的 `DataLength` 是 `FDCAN_DLC_BYTES_x` 编码（值<<16），转字节数要 `>>16`。
- FDCAN 内核时钟若被改过 mux（不指向 PLL3），位时序全部重算——动 Clock 树后必看波特率显示。
