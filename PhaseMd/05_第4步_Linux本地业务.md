## 1. 业务状态机

```
 IDLE ──CAN遮光事件(0x01)──► CAR_WAIT（登记待识别车，起 3s 识别超时计时）
   ▲                            │ 共享内存事件字 0x01 通知 Core1 启动识别（第6步接通；本步由 core1_stub 模拟）
   │                            ▼
   │ 关闸/超时/降级 ◄── RECOGNIZING（等 Core1 结果；本步恒超时）
   │                            │ 结果到达（shm evt_bits_c1=0x02 + plate/confidence，第6步起生效）
   │                            ▼
   └── COOL_DOWN ◄──开闸指令── WHITELIST_CHECK ──不过──► DENY（记录+提示，不开闸）
        (3~5s 冷却防重复)            │ 通过
                                    ▼
                                GATE_OPEN（RPMSG 0x11 → M4 → CAN 0x100 → SG90）
```

- **触发唯一性**：只有 CAN 遮光事件进 CAR_WAIT；手动/上位机开闸走**独立降级通道**，不过识别流程。
- **数据单向**：硬件状态/事件向上汇总，业务指令向下下发。

## 2. 任务清单

### P4-01 状态机框架 ✅代码
- 单线程事件驱动：epoll 统一等待（rpmsg 队列 eventfd、200ms timerfd 轮询 shm 结果/远程请求/事件字、signalfd 收 SIGINT/SIGTERM 优雅退出）。
- 每个**状态转换**打日志（毫秒时间戳，第6/8步延迟测量依赖）。
- **验收**：状态图上每条边都有日志可回放（S1~S12 覆盖全边）。

### P4-02 识别超时与降级路径 ✅代码
- CAR_WAIT 起 3s 计时：超时 → DENY_TIMEOUT → UI 提示 → **手动/UI 开闸通道保持可用**（Task 1.3 交付标准：识别链路失效不阻塞控制）。
- Core1 失联（心跳断，P4-06）→ 跳过识别环节全靠降级通道。
- 超时口径（第7步起扩展）：默认 3s；若 Core1 置 shm `cloud_pending`（云兜底进行中）→ 延长至 6s 硬上限，见 P7-04。
- **验收**：宿主自测 S2（超时拒绝 + 迟到结果丢弃）、S3（3s→6s 硬上限）、S4（Core1 失联立即降级）已过；真机实测待板验。

## 避坑

- Core0 **不跑任何图像/Qt/云请求**（负载隔离红线）。
- ~~502 端口~~ 已随 Modbus-TCP 移除而作废；本组件不监听任何网络端口。
- **共享内存契约**：Core0 写 / Core1 读 `park_shm`（v3，76B）；Core1 **必须 `O_RDWR` + `PROT_READ|PROT_WRITE`**（否则心跳/结果/远程请求写不进 → Core0 判其失联）。跨进程事件走 shm 事件字（`evt_bits_c0/c1` + `evt_seq_c0/c1`），**匿名 eventfd 无法跨进程共享**，不要改回去；读侧 200ms 轮询满足 ≤500ms KPI。契约见 `docs/protocols.md` §4。
- 3s 识别超时（Core0 视角）与第7步 DeepSeek 5s 超时的衔接已定稿：默认 3s；`cloud_pending` 置位时延长至 6s 硬上限（云限 5s），到点必降级（见 P7-04，K2 实测）。
- 开闸指令幂等：同一车牌结果重复到达不重复发闸（COOL_DOWN 兜底）。
- RPMSG `0x21` 事件帧里带 lux/drop% 原始值，业务日志全量留痕，便于现场调遮光敏感度。
