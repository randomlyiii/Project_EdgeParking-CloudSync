# 第 4 步 · Linux 本地业务（Core0 状态机 + 上位机 + 监督）

> 步骤：4 ｜ 前置：G3（RPMSG 通道） ｜ 产出：`core0_service/business|protocol|storage|ipc_shm/` 本地业务闭环 ｜ 验收门：G4
> 定位（Task.md 第二节）：Core0 轻负载、高可靠、常驻高优先级、绑 CPU0（绑核动作在第6步 P6-03，本步先留口）。
> 本步**视觉未接入**：识别结果事件只有接口没有生产者，RECOGNIZING 必然走超时分支——这正是本步要验证的降级路径。

## 1. 业务状态机

```
 IDLE ──CAN遮光事件(0x01)──► CAR_WAIT（登记待识别车，起 3s 识别超时计时）
   ▲                            │ eventfd 通知 Core1 启动识别流程（第6步接通；本步为空操作）
   │                            ▼
   │ 关闸/超时/降级 ◄── RECOGNIZING（等 Core1 结果；本步恒超时）
   │                            │ 结果到达（eventfd，第6步起生效）
   │                            ▼
   └── COOL_DOWN ◄──开闸指令── WHITELIST_CHECK ──不过──► DENY（记录+提示，不开闸）
        (3~5s 冷却防重复)            │ 通过
                                    ▼
                                GATE_OPEN（RPMSG 0x11 → M4 → CAN 0x100 → SG90）
```

- **触发唯一性**：只有 CAN 遮光事件进 CAR_WAIT；手动/上位机开闸走**独立降级通道**，不过识别流程。
- **数据单向**：硬件状态/事件向上汇总，业务指令向下下发。

## 2. 任务清单

### P4-01 状态机框架 ⬜
- 单线程事件驱动：epoll 统一等待（rpmsg 队列 eventfd、core1 结果 eventfd（预留）、3s 超时 timerfd、Modbus 事件）。
- 每个**状态转换**打日志（毫秒时间戳，第6/8步延迟测量依赖）。
- **验收**：状态图上每条边都有日志可回放。

### P4-02 识别超时与降级路径 ⬜
- CAR_WAIT 起 3s timerfd：超时 → DENY_TIMEOUT → UI/上位机提示 → **手动/上位机开闸通道保持可用**（Task 1.3 交付标准：识别链路失效不阻塞控制）。
- Core1 失联（心跳断，P4-06）→ 跳过识别环节全靠降级通道。
- 超时口径（第7步起扩展）：默认 3s；若 Core1 置 shm `cloud_pending`（云兜底进行中）→ 延长至 6s 硬上限，见 P7-04。
- **验收**：本步实测——遮光后 3s 走超时分支，随后手动开闸正常。

### P4-03 白名单模块 ⬜
- 内存表（车牌→权限/有效期），加载自配置文件；
- 上位机增删（Modbus 写，见 P4-05 寄存器区）；
- 策略：精确匹配；DENY 留痕。
- **验收**：白名单内/外两路行为正确（第6步接上真车牌后回归）。

### P4-04 车位统计 ⬜
- 演示口径：进出计数状态机（开闸 + 遮光恢复 = 车辆通过 → 按入/出口模式计数）；无占用传感器（可选件）时用此口径，注释写明。
- 空位 = 总位数 − 已入，限幅 [0, 总位数]。
- **验收**：模拟进出 10 轮计数准确。

### P4-05 Modbus-TCP 从站（`protocol/`）⬜
- libmodbus（交叉编译或静态链）；TCP 502（测试期 1502，交付前定）；挂进 epoll。
- 寄存器表（权威母本=文档 10）：

| 地址 | R/W | 说明 |
|---|---|---|
| 0x0000 | R | 空闲车位数 |
| 0x0001 | R | 已停车辆数 |
| 0x0002 | R | 闸状态（0 关/1 开） |
| 0x0003 | R | 最近车牌长度 |
| 0x0004~0x000D | R | 最近车牌 ASCII（≤10 字符） |
| 0x0010~0x002F | R/W | 白名单槽 0~7（每槽 8 字符 = 4 寄存器，共 32 寄存器） |
| 0x0030 | W | 远程开闸脉冲（写 1 生效，自清零） |
| 0x0031 | W | 远程关闸脉冲 |
| 0x0040 | R | 故障字（bit0 rpmsg断 bit1 M4离线 bit2 core1失联 bit3 CAN错误 bit4 云兜底失败） |
| 0x0041 | R | 心跳计数（每秒 +1） |

- **验收（KPI）**：PC Modbus Poll 读写 ≤50ms；写 0x0030=1 → SG90 动作。

### P4-06 watchdog 检测 Core1 ⬜
- Core1 每 1s 在共享内存心跳字 +1（shm 第6步建好前，先用"结果 eventfd 活性"代替）；Core0 检 3s 无变化 → 故障字 bit2 + 日志。
- 实际拉起交给 systemd `Restart=`（第8步 P8-05），Core0 只负责**检测与上报**（双保险原则）。
- **验收**：本步用打桩进程模拟心跳停止 → ≤3s 故障字置位。

### P4-07 本地存储（可选，默认关）⬜
- `ENABLE_STORAGE` 编译宏/环境变量控制；SQLite3 WAL + 独立低频异步写线程；**状态变更才落盘**（eMMC 寿命）。
- 表：`events(ts,type,plate,detail)`、`gate_log(ts,action,source)`。
- **验收**：开关联动编译；运行 1 小时库增长 KB 级。

### P4-08 日志系统 ⬜
- 统一 `LOG(level, tag, fmt)`：stdout(journald) + 可选文件；DEBUG/INFO/WARN/ERROR；每条带 ms 时间戳。
- **验收**：第6/8步埋点依赖此模块。

## 避坑

- Core0 **不跑任何图像/Qt/云请求**（负载隔离红线）。
- 502 端口 <1024 需 root 或 `CAP_NET_BIND_SERVICE`；测试期 1502。
- 3s 识别超时（Core0 视角）与第7步 DeepSeek 5s 超时的衔接已定稿：默认 3s；`cloud_pending` 置位时延长至 6s 硬上限（云限 5s），到点必降级（见 P7-04，K2 实测）。
- 开闸指令幂等：同一车牌结果重复到达不重复发闸（COOL_DOWN 兜底）。
- RPMSG `0x21` 事件帧里带 lux/drop% 原始值，业务日志全量留痕，便于现场调遮光敏感度。
