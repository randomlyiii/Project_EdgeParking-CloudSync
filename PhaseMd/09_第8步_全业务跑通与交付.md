## 2. 故障注入与降级演练

### P8-03 注入矩阵 ⬜
| 注入 | 期望行为 |
|---|---|
| 拔 K210 串口 | Core1 预览置断+识别线不可用；Core0 遮光事件 3s 超时 → 降级提示；手动/LCD 开闸正常 |
| 断外网 | 云兜底 5s 失败回退端侧；本地闭环照常；（可选）MQTT 队列暂存 |
| kill core1 进程 | ≤3s 故障字 bit2；systemd 拉起（P8-05）；期间 Core0 业务照常 |
| 拔 CAN 线 | M4 3s 判从节点离线 → RPMSG 0x22 → Core0 故障字 bit1 → LCD UI 可见；插回自动恢复 |
| 杀 core0 进程 | systemd 拉起；rpmsg 断链恢复路径生效（状态重同步） |
| M4 固件 remoteproc stop/start | Core0 走断链恢复，不崩溃 |
- **验收**：六注入全部按期望恢复，无人工干预（除拔插线）。

## 3. 部署固化（`deploy/systemd/`）

### P8-04 systemd unit ⬜
```ini
# /etc/systemd/system/m4-firmware.service
[Unit]
Description=Load M4 firmware via remoteproc
[Service]
Type=oneshot
ExecStart=/bin/sh -c 'echo start > /sys/class/remoteproc/remoteprocX/state'
RemainAfterExit=yes
[Install]
WantedBy=multi-user.target

# /etc/systemd/system/core0.service
[Unit]
Description=Park core0 service
After=m4-firmware.service
Requires=m4-firmware.service
[Service]
ExecStart=/opt/park/core0_service
CPUAffinity=0
Nice=-10
Restart=always
RestartSec=1
[Install]
WantedBy=multi-user.target

# /etc/systemd/system/core1.service
[Unit]
Description=Park core1 UI
After=core0.service
[Service]
ExecStart=/opt/park/core1_ui
CPUAffinity=1
Restart=always
RestartSec=1
Environment=QT_QPA_PLATFORM=linuxfb
[Install]
WantedBy=multi-user.target
```
- 启动顺序（Task.md 第九节红线）：**remoteproc 装载 M4 → rpmsg 就绪 → Core0 → Core1(k210_link→Qt)**；每级未就绪有重试与降级，不阻塞启动。
- 开机自启整链验证：断电重启 3 次，全部自动到工作态。
- **验收**：三 unit enable 后冷启动自动全通。

### P8-05 看门狗双保险 ⬜
- systemd `Restart=always`（拉起）+ 应用层检测（P4-06，上报故障字）都已就位；
- 演练：逐个 kill 进程验证拉起时间（≤5s）与故障上报联动。
- **验收**：任一进程崩溃可自动恢复，Core0 控制链路全程不受影响（KPI）。

### P8-06 日志与持久化 ⬜
- journald 持久化（`Storage=persistent`）；应用文件日志轮转（logrotate 或按大小自转，上限几十 MB）。
- **验收**：重启后日志可回溯。

## 避坑

- systemd 起的进程环境与手工调试不同（PATH/环境变量/工作目录）——Key 文件、Qt 平台变量全部写进 unit `Environment=`。
- `CPUAffinity=` 与第6步 isolcpus 联合生效才达标，缺一都可能在压测时露馅。
- 长稳期间别插拔演示外设；记录的所有"偶发一次"都要当线索查（长稳的意义就是抓偶发）。
- remoteproc 的 `remoteprocX` 编号在不同内核镜像可能不同，unit 里用探测脚本或固定镜像后写死。
