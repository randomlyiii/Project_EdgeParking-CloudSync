> 步骤：6 ｜ 前置：G4（本地业务）+ G5（K210 通讯） ｜ 产出：**本地全闭环**（遮光→识别→开闸→LCD UI，无云） ｜ 验收门：G6
> 本步把第4步的状态机 stub 换成真识别结果，把两条并行线（CAN 底盘线、K210 视觉线）在 Core0/Core1 之间焊起来。

## 1. 双 A7 IPC（`core0_service/ipc_shm/` + Core1 侧）

### P6-01 共享内存布局 ✅ 代码（2026-09-11）
- **已落地**：`park_shm_t` **v3、`sizeof==76`**，权威定义在 `docs/protocols.md` §4，双副本 `core0_service/ipc_shm/park_shm.h` 与 `core1_ui/qt_gui/src/park_shm.h` 逐字节一致 + 编译期偏移断言（48/52/56/60/68）。相对下面的原始草案追加了 v2 尾字段（`req_gate_open/close`、`fault_bits`、`conf_threshold`）与 v3 事件字（见 P6-02）。
- `shm_open("/park_shm")` + `ftruncate` + `mmap`；结构体带版本号/seq，读方必须能识别陈旧数据（Task.md 6.2）：

```c
typedef struct {
    uint32_t magic, version;
    volatile uint32_t seq;            /* 写方递增；读方前后双读比对防撕裂 */
    /* --- core0 → core1（UI/业务数据源） --- */
    int32_t  free_slots, used_slots;
    uint8_t  gate_state;              /* 0 关 1 开 */
    uint8_t  link_flags;              /* bit0 rpmsg bit1 m4在线 bit2 core1在线 */
    uint8_t  recog_pending;           /* 有待识别车辆 */
    /* --- core1 → core0（识别结果） --- */
    uint8_t  cloud_pending;           /* 云兜底进行中：Core0 识别超时 3s→6s（P7-04） */
    uint8_t  result_valid;            /* 读后由 core0 清 */
    uint8_t  result_source;           /* 0=edge 1=cloud */
    float    confidence;
    char     plate[16];
    /* --- 心跳 --- */
    volatile uint32_t hb_core1;       /* core1 每 1s +1，core0 检 3s */
} park_shm_t;
```
- 大块数据（跨核传抓拍 JPEG）用**双缓冲环形区**防撕裂；本 demo 识别结果是小 JSON，JPEG 留在 Core1 本地（图像不外溢原则）。
- **验收**：两端进程同时读写 10 分钟无撕裂/陈旧误用。

### P6-02 跨进程事件通道 ✅ 代码（2026-09-11；方案由 eventfd 改为 shm 事件字）
- **⚠️ 关键结论：匿名 eventfd 无法跨进程**（另一进程打不开这个 fd，`EFD_CLOEXEC` 也会跨 exec 丢失）→ v3 改为共享内存里的 `evt_seq_c0/c1` + `evt_bits_c0/c1`：生产方**先置位、再序号 +1**，消费方轮询序号变化 → 读位 → 处理完清位。下表事件码即位号（`PARK_EVB(code) = 1u << code`）。
- 轮询周期：Core0 侧 timerfd tick、Core1 侧 `IpcWriter::onEvtPoll` 200ms ⇒ 状态刷新 ≤500ms 预算满足。
- **验收**：`evt_seq_c1` 随识别结果递增且 Core0 读到 RESULT 位；Core0 发 TRIGGER/STATE 时 Core1 日志有对应事件。
- 事件驱动代替轮询（Task.md 6.2）；事件码：

| 事件码 | 方向 | 含义 |
|---|---|---|
| 0x01 | core0→core1 | 触发识别（CAR_WAIT 登记） |
| 0x02 | core1→core0 | 识别结果到达（result_valid 已置） |
| 0x03 | core0→core1 | 状态变更（UI 刷新） |
| 0x04 | core0→core1 | 重同步请求 |

- **验收**：两边 epoll 都用 eventfd 驱动，CPU 空载占用低。

## 2. 核隔离落地（Task.md 第二节，缺一不可）

### P6-03 内核与进程绑核 ⬜
1. **内核 cmdline**（100ASK 镜像按其 boot 方式改 bootargs/_extlinux）：`isolcpus=1 nohz_full=1 rcu_nocbs=1`；验证 `cat /proc/cmdline`。
2. **中断亲和**：脚本把网卡/串口 irq 移到 CPU0（`/proc/irq/*/smp_affinity`）。
3. **进程绑定**：systemd `CPUAffinity=`（第8步固化）或启动脚本 `taskset -c 0 core0_service`、`taskset -c 1 core1_ui`；验证 `taskset -pc <pid>` / `ps -o psr`。
4. **优先级**：Core0 关键进程 SCHED_FIFO 或 nice −10；Core1 普通优先级。
- ⚠️ isolcpus=1 后若 core1 忘了绑核，所有负载挤 CPU0——绑核与 isolcpus 必须同时生效。
- **验收**：两进程分别稳定跑在 CPU0/CPU1。

### P6-04 业务对接（换掉第4步 stub）✅ 代码（2026-09-11，板端联调待复验）
- **Core1 写端已落地**：`core1_ui/qt_gui/src/ipc_writer.{h,cpp}`（`IpcWriter`，规格 `.codeartsdoer/specs/core1_business/spec.md`）——`O_RDWR`+`PROT_READ|PROT_WRITE` 挂载 `/park_shm`、magic/version 自检（不符则拒绝写入并 ERROR，不静默）、1s `hb_core1` 心跳、识别结果回写（`plate/confidence/result_source/result_valid` + `evt RESULT`）、低置信/失败置 `cloud_pending`、远程开/关闸脉冲 `req_gate_*`、200ms 消费 `evt_c0`。
- **触发源（spec 5.6「可插拔」）**：底栏「开闸/关闸」触摸按钮（板端无键盘，触摸经 libinput 走鼠标事件）+ `O`/`C` 热键 + 外部工具直写 shm，三者共用同一 `gateRequested()` → 脉冲写入口。
- 装配在 `src/main.cpp`（`writer.start()` / `writer.stop()`）；静态门禁 `python3 core1_ui/qt_gui/tools/check_static.py` **PASS**，其中含**负向断言**：写端绝不允许出现对 `magic/version/seq/free_slots/used_slots/gate_state/link_flags/recog_pending/fault_bits/conf_threshold/evt_*_c0` 的赋值。
- **Core0 侧无需改动**：结果/请求由 `ipc_shm_take_result()`、`ipc_shm_take_requests()` 轮询消费，事件位只作日志（结果不依赖事件不丢）。
- **验收（板上）**：见 `core1_ui/qt_gui/README.md` §5。期望：屏上 `CORE1:在线`、日志 `ipc-writer: /park_shm attached (v3)`；点「开闸」→ `ipc-writer: gate open requested` + `[remote] gate OPEN request from core1 (ui)` + `[gate] OPEN command sent (source=ui)` → C8T6 舵机动作。
- Core0：CAR_WAIT 登记 → 置 `recog_pending` + 发 eventfd 0x01；收 0x02 → 读 `plate/confidence/source` → 白名单 → 开闸/拒；
- Core1：k210_link 订阅 0x01 → 启动识别状态机（第5步 P5-10）；结果写 shm + eventfd 0x02；
- **验收**：日志可见"事件→识别→结果→校验→开闸"全链路。

## 避坑

- 共享结构体字段改动必须两端同步编译（放公共头 + version 字段自检，不匹配则拒绝启动）。
- `recog_pending` 只在 CAR_WAIT 置位、结果/超时即清，防旧触发重复识别。
- eventfd 计数器是累积值，读后要清零（`read` 一次消费）；别拿它当队列长度。
- isolcpus 调试期可先不加（先把功能打通），但 G6 验收前必须加上并复测。
