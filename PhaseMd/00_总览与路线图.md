## 一、实现主线（严格串行推进，步内任务可并行）

```
第0步 环境/接线 ─► 第1步 下位机 ─► 第2步 M4↔下位机(CAN) ─► 第3步 Linux↔M4(RPMSG) ─► 第4步 Linux本地业务
                                                                                        │
                  第5步 K210↔Linux(并行线，不依赖第2~4步) ─────────────────────────────┤
                                                                                        ▼
                                              第6步 本地业务联通(本地全闭环) ─► 第7步 Linux↔云端 ─► 第8步 全业务跑通(交付)
```

| 步 | 名称 | 做完的标志（验收门） | 文档 |
|---|---|---|---|
| 0 | 环境与硬件准备 | 工具链可用、物料齐、接线就位（60Ω/共地实测） | 01 |
| 1 | 下位机 C8T6 本地功能 | OLED 显示 + BH1750 遮光状态机 + SG90 本地自检动作，全部不依赖对外通讯 | 02 |
| 2 | M4↔下位机 CAN 通讯 | 500k 双向：C8T6 发 0x200/0x210 → M4 收；M4 发 0x100 → SG90 动作 | 03 |
| 3 | Linux↔M4 RPMSG 通讯 | remoteproc 加载 M4 → ttyRPMSG0 事件上行/指令下行；断链 ≤1s 检出、恢复重同步 | 04 |
| 4 | Linux 本地业务 | Core0 状态机跑通：遮光事件→登记→（识别未接入走超时）→**手动/上位机开闸闭环**；Modbus-TCP 可控 | 05 |
| 5 | K210↔Linux 通讯 | K210 预览流常开 + 抓拍指令触发识别；Core1 k210_link 重组/解析全通（PC 直连先行） | 06 |
| 6 | 本地业务联通 | **本地全闭环**：遮光→识别→白名单→开闸→UI/上位机刷新，≤3s（无云参与场景） | 07 |
| 7 | Linux↔云端通讯 | DeepSeek Vision 兜底接入（置信度不足自动调用）；（可选）MQTT 云平台 + SQLite | 08 |
| 8 | 全业务跑通 | 全链路 KPI 实测达标 + systemd 自启 + 看门狗 + 24h 长稳 = **交付** | 09 |

## 二、架构快照（以最新决策为准，覆盖 Task.md 旧描述）

**读 Task.md 时做以下映射（本目录所有文档均按新版架构写）**：

| Task.md 旧描述 | 最新落地 |
|---|---|
| M4 红外传感器车辆到位检测 | **C8T6 BH1750 遮光检测**（百分比掉点状态机），CAN 0x200 上报 |
| M4 CAN 道闸控制器 | **C8T6 SG90 舵机**（PWM），收 CAN 0x100 执行开/关闸 |
| M4 IO 采集 / 车位传感器 | 暂无器件，M4 职责收敛为 **CAN↔RPMSG 网关 + 心跳/故障汇总** |
| A7 本地 TFLite 车牌识别 | **外接 K210 KPU**，预览流常开 + 指令触发识别 |

**通道矩阵 v2**（Task.md 6.3 的 v1 之上新增通道 0）：

| # | 通道 | 方向 | 载体 | 内容 |
|---|---|---|---|---|
| 0 | C8T6 ↔ M4 | 双向 | 经典 CAN 2.0 / 500kbps | 0x200 遮光事件 ↑；0x100 开闸指令 ↓；0x210 心跳 ↑ |
| 1 | M4 ↔ Core0 | 双向 | RPMSG（ttyRPMSG0） | CAN 事件/心跳 ↑；开闸/配置指令 ↓ |
| 2 | K210 ↔ Core1 | 双向 | UART ≥921600 | JPEG 预览 ↓（常开）；抓拍指令 ↑；识别 JSON ↓ |
| 3/4 | Core0 ↔ Core1 | 双向 | 共享内存 + eventfd | 识别结果 / 触发事件 / UI 状态 |
| 5 | Core0 ↔ 上位机 | 双向 | Modbus-TCP | 查询 / 远程开闸 / 配置 |
| 6 | Core1 → 云 | 单向 | HTTPS | 车牌图像 Base64 → DeepSeek Vision |
| 7 | Core0 → 云平台（可选） | 单向 | MQTT | 记录 / 心跳 / 故障 |

## 三、全链路业务闭环（第6步联调、第8步验收的对象）

```
 车辆驶入遮住 BH1750
      │ ①百分比掉点状态机判"到位"（C8T6，第1步）
      ▼
 CAN 0x200 [event=0x01, lux, drop%]        （第2步）
      │ ②M4 FDCAN1 收帧入队
      ▼
 RPMSG 上报 ──► A7-Core0：登记待识别车辆 + 3s 超时看门狗   （第3/4步）
      │ ③eventfd 通知 Core1
      ▼
 Core1 k210_link ──CMD_RECOGNIZE──► K210 KPU 抓拍识别      （第5步）
      │                                  │ 置信度不足
      │ ④结果 JSON                       ▼
      │                          ⑤Core1 调 DeepSeek Vision（5s 超时，失败回退端侧，第7步）
      ▼
 Core0 白名单校验 ──► RPMSG 开闸指令 ──► M4 FDCAN 发 0x100 ──► C8T6 SG90 开闸   （第4/2步）
      │                                                        │
      └──► Qt UI 刷新 / 上位机同步 /（第7步）云端上报            └─ OLED Gate 行变 Open
```

## 四、任务编号与状态约定

- 编号 `P<步>-<序号>`：`P2-03` = 第2步第3项；支撑文档任务用 `Q-xx`（Qt）。
- 状态：⬜ 未开始 ｜ 🟨 进行中 ｜ ✅ 完成（已按当前真实进度预标：C8T6 的 OLED/软件 I2C/BH1750 驱动已完成）。
- **推进纪律**：上一步验收门全部打钩才进下一步；每步完成后把进度与踩坑同步进 `AGENTS.md`。
- 步内可并行举例：第5步（K210 线）与第2~4步完全独立，可由两人并行开工。

## 五、全局 KPI 摘要（测量方法与用例见文档 12）

| 指标 | 目标 |
|---|---|
| 触发闭环延迟（遮光→开闸指令发出） | ≤ 3s（云兜底参与时另计） |
| rpmsg 断链检出 | ≤ 1s，恢复不丢业务状态 |
| K210 端侧识别准确率（白天） | ≥ 90%，不足时云兜底 |
| UART 预览流 | ≥ 5fps、无花屏，识别运行不影响预览 |
| 状态刷新（Core0→UI） | ≤ 500ms |
| 稳定性 | Core1 进程崩溃自动拉起；Core0 控制链路不受影响 |
| 遮光误触发 | 去抖（连续 3 次）+ 回滞（60%/20%）后可接受 |
