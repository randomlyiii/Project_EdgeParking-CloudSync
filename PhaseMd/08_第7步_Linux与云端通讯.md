# 第 7 步 · Linux ↔ 云端通讯（DeepSeek 兜底 + 可选云平台）

> 步骤：7 ｜ 前置：G6（本地全闭环） ｜ 产出：边云协同实时兜底 +（可选）MQTT 云平台/SQLite ｜ 验收门：G7
> 边云协同两种形态（README）：①识别置信度不足时调 **DeepSeek Vision API**（实时，本步必做）；②云平台数据上报（**可选**，P7-09~11）。
> 约束：云请求**单次触发调用**不循环；5s 超时不阻塞本地业务与开闸降级；云故障时设备本地照常运行。

## 1. DeepSeek Vision 兜底（`core1_ui/cloud_api/`，跑在 Core1）

### P7-01 libcurl 集成 ⬜
- Core1 侧链接 libcurl（交叉编译确认或用 rootfs 自带）；HTTPS 证书路径/校验策略确定。
- **验收**：最小 GET 示例在板上跑通（如拉取任意 https 页）。

### P7-02 请求构造 ⬜
- 图像源：优先 K210 失败时附回的抓拍 JPEG（P5-07 的 0xC3），退而取最近一帧预览；
- Base64 → `data:image/jpeg;base64,...` 嵌入 JSON：

```json
POST https://api.deepseek.com/chat/completions
Authorization: Bearer $DEEPSEEK_API_KEY
{"model":"<以官方现行 Vision 能力为准>",
 "messages":[{"role":"user","content":[
   {"type":"text","text":"<见 P7-03 Prompt>"},
   {"type":"image_url","image_url":{"url":"data:image/jpeg;base64,<...>"}}]}],
 "max_tokens":64,"temperature":0}
```
- ⚠️ **接口核实点**：DeepSeek 官方 API 对图像输入的支持以现行文档为准；若官方 chat API 不支持图像，改用其 Vision 兼容端点或按 README 口径换成同协议服务——**此核实完成后回填文档 10 的云端章**。
- **验收**：PC 端 curl 先打通请求/响应格式，再上板。

### P7-03 Prompt 约束输出 ⬜
- 中文 Prompt（示例）："你是车牌识别器。识别图中车牌，只输出 JSON：{\"plate\":\"省份简称+字母+5位\",\"confidence\":0.95}；无法识别则 plate 为空字符串、confidence 为 0。不要输出其他任何文字。"
- **验收**：20 张测试图输出 100% 合法 JSON（不合法也要能被 P7-05 容错）。

### P7-04 超时与重试策略 ⬜
- `CURLOPT_TIMEOUT = 5s`（KPI 口径）；**单次触发单次调用**（识别事件驱动，不循环轮询）；
- 失败重试 ≤1 次；仍失败 → 返回"云兜底失败"，业务回退端侧结果/超时降级路径。
- **与 Core0 超时的衔接（定稿策略）**：Core0 默认 3s 识别超时；Core1 发起云兜底时置 shm `cloud_pending`，Core0 在 3s 到点发现该标志则延长至 **6s 硬上限**（云限 5s + 余量），到点仍未回必走降级——云永远不阻塞降级通道。
- **验收**：断网注入 → 5s 内返回失败，本地业务不阻塞。

### P7-05 响应解析容错 ⬜
- 剥离可能的 markdown 代码块/前后杂文 → 提取 JSON → 校验字符集；
- 解析失败按"云兜底失败"处理。
- **验收**：构造 3 种脏响应（代码块包裹/纯文本/截断）均安全落地。

### P7-06 触发策略 ⬜
- 触发条件（Task 2.2）：K210 置信度 < `RECOG_CONF_TH`、识别失败、或 K210 链路异常但网络可用；
- 结果统一格式回注主流程：写 shm `result_source=1(cloud)` + eventfd 0x02，Core0 校验逻辑不区分来源。
- **验收**：低置信样本自动走云、成功开闸；云失败自动回退端侧结果/降级。

### P7-07 API Key 管理 ⬜
- 环境变量/`/etc/park/cloud.env` 注入；**不入 git**（.gitignore 检查）。
- **验收**：仓库内 grep 不到 key。

## 2. 云平台上报（可选，Task 1.6 / 阶段 4）

### P7-08 MQTT 接入 ⬜
- Broker 选型：局域网 mosquitto（演示）或公有云 EMQX；Core0 侧用 paho.mqtt.c / libmosquitto，**低优先级线程**，不与 1.1~1.3 抢核抢时。
- 主题设计（写入文档 10 云端章）：
  - `park/{sn}/status`：车位/闸/故障字/心跳（周期 + 变更）
  - `park/{sn}/events`：进出记录、开闸记录
  - `park/{sn}/cmd`（下行，可选）：远程参数配置
- **验收**：MQTTX 订阅端能看到上报。

### P7-09 离线缓存与补传 ⬜
- 断网时本地队列（内存 + 可选落盘）暂存，重连后按 seq 补传、去重。
- **验收**：拔网 2 分钟再恢复，事件不丢不重。

### P7-10 SQLite 启用（联动 P4-07）⬜
- 若云上报需要历史查询，打开 `ENABLE_STORAGE` 验证联动（记录既是本地留痕也是补传数据源）。
- **验收**：断网期间记录落库，恢复后补传完成。

### P7-11 云故障不影响本地（验收红线）⬜
- 注入：断外网、云 API 5xx、Broker 不可达——本地闭环（第6步 P6-06 场景）全部照常。
- **验收**：三注入场景下 P6-06 全过。

## 避坑

- DeepSeek 请求跑在 **Core1**（Core0 禁云请求）；图像 Base64 内存峰值注意释放（单帧 JPEG ~10KB，Base64 ~14KB，无压力，但别缓存多帧）。
- 5s 超时是"云请求自身"的；不要让 Core0 的 3s 识别超时被云请求拖死——两计时器独立。
- 云兜底结果同样要过白名单校验（来源不豁免）。
- 演示现场网络不稳：准备手机热点 + 断网演练脚本。
