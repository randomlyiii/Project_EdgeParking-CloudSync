# 排障速查手册（按子系统聚合）

> 支撑文档：联调卡住先查这里；确认是新坑（本表没有的）→ 修好后**把现象+根因回填本表并同步 AGENTS.md**。

## 1. C8T6 · OLED / 软件 I2C

| 现象 | 排查顺序 |
|---|---|
| 黑屏 | 供电/上电 20ms 时序 → init 平铺序列（参考工程 OLED_Config，逐字节命令+参数）→ PB8/PB9 上拉 → 模块好坏 |
| 残影 | 整行空格补足 16 列再写 → `UpdateScreen` 集中上屏 |
| 碎字符/感叹号乱码 | bit-bang 被抢占：确认 `WriteCmd/WriteData` 临界区（__disable_irq）在；仍现 → OLED_Task 改"内容变化才刷" |
| PC13 闪码 | 6=总线+OLED OK；1/3=GPIO 层；2/4=线拉死/无上拉；5=0x78 无 ACK（对照 AGENTS.md v5 判定表） |
| w/o/r"缺顶" | 江协 8x16 小写 x-height 字体设计（rows 7-13），非 bug |

## 2. C8T6 · BH1750 / 遮光

| 现象 | 排查顺序 |
|---|---|
| 读数 0xFFFF | 地址 0x23（ADDR 悬空）→ sw_i2c 两字节读时序（START|0x47|ACK+NACK）→ 与 OLED 共线时序冲突（上电顺序） |
| 遮光不触发 | OLED 看 drop% 是否贴合 → `SHADE_DROP_PERCENT` 调低 → `SHADE_CONFIRM_N` 调小（先诊断后调参） |
| 误触发 | drop% 偶发越阈 → `SHADE_CONFIRM_N` 调大 → 确认 SHADED 态基线冻结生效 |
| 灯光变化误报 | EMA 快速跟上逻辑（lux≥baseline 时 baseline=lux）是否在 |
| 恢复不上报 | 回滞 20% 未达 → 现场光太暗基线塌陷 → 重新上电重建基线 |

## 3. C8T6 · SG90

| 现象 | 排查顺序 |
|---|---|
| 不动 | 50Hz（PSC71/ARR19999）→ PWM Start 一次确认 → CCR 值 500~2500 → 信号线 |
| 抖动/啸叫 | 独立 5~6V 供电共地 → 缓动步进（每 20ms ±100µs）别高频突变 CCR → 行程避开两端极限 |
| MCU 复位 | 舵机从 MCU 5V 取电（启动电流冲击）→ 换独立电源 |

## 4. CAN（C8T6 ↔ M4）

| 现象 | 排查顺序 |
|---|---|
| 完全收不到 | 两端实际波特率（CubeMX 显示值）→ H/L 反接 → 60Ω → 共地 → 过滤器 → **M4 Filter Nbr=0 / RxFifo0ElmtsNbr=0（经典坑）** → C8T6 FilterIdHigh 忘 <<5 |
| 时通时断 | 单终端电阻 → 杜邦线接触 → 采样点差 >5% |
| 字段乱 | lux 大端 → DLC≠8 → M4 `DataLength>>16` |
| 发送失败 | 邮箱满未等 TxOK → 对端未 Start → `AddTxMessage` 返回值 |
| M4 挂死 | Bus_Off 未恢复（P3-04）→ 错误计数看 `GetErrorCount` |
| 帧间隔异常 | C8T6 心跳被阻塞任务拖慢（CAN 发送别放软件 I2C 临界区内） |

## 5. RPMSG / M4 加载

| 现象 | 排查顺序 |
|---|---|
| 无 /dev/ttyRPMSG0 | rsc_table 在固件里 → remoteproc state=start 的 dmesg 报错 → 固件路径/权限 → 内核 CONFIG_RPMSG_CHAR |
| M4 启动即崩 | OpenAMP 初始化顺序（MX_OPENAMP_Init 在 osKernelStart 前）→ IPCC 中断使能 |
| 收不到但 CAN 正常 | M4 事件槽→RPMSG 转发逻辑 → rpmsg 缓冲满丢弃计数 |
| 断链不报 | 心跳两侧都在发？→ 超时阈值 1s 生效？→ 业务层读 LINK_DOWN |
| 恢复后状态错 | 0x13 全量重同步 → 旧 seq 未丢弃 |

## 6. K210 / UART

| 现象 | 排查顺序 |
|---|---|
| 无输出 | 供电（带供电 HUB）→ TX/RX 交叉 → 共地 → 波特率 → 模块串口脚丝印（Maix Bit=A16/A17） |
| 花屏/丢帧多 | 单帧体积太大（质量调低）→ 波特率降回 921600 → 发送节流 |
| 莫名复位 | USB 供电不足 → 独立 5V |
| 识别无结果 | 模型加载失败日志 → 输入尺寸 ≤320×240 → 一次触发一次结果（busy 丢弃逻辑） |
| 识别期间预览停 | 预期行为（KPU 竞争），确认恢复续流 + seq 连续即可 |

## 7. Core0 / Core1 / Linux

| 现象 | 排查顺序 |
|---|---|
| 状态机卡死 | 每条边的日志（P4-01）→ eventfd read 后清零？→ timerfd 3s 生效？ |
| 白名单不生效 | 寄存器写入格式（ASCII ×2 寄存器）→ 内存表加载 |
| 双核抢占 | `taskset -pc` 确认绑定 → isolcpus cmdline → 中断亲和脚本 |
| shm 撕裂 | seq 双读比对 → version 校验 → 两端结构体头是否同版本 |
| UI 卡顿 | JPEG 解码移出 UI 线程 → 帧队列取最新 → 预览分辨率降级 |

## 8. 部署 / systemd

| 现象 | 排查顺序 |
|---|---|
| 开机不启动 | `systemctl status` → unit 依赖顺序（m4→core0→core1）→ `journalctl -u xxx` |
| 手工好、systemd 坏 | 环境变量（QT_QPA_PLATFORM/字体/Key env 文件）→ 工作目录 → 权限 |
| 拉起风暴 | `RestartSec=1` + 崩溃循环 → 先查根因再放宽 RestartSec |
| remoteproc 编号漂移 | unit 内探测脚本写 start 或固定镜像 |

## 9. 云端

| 现象 | 排查顺序 |
|---|---|
| 云请求全失败 | Key/配额 → PC curl 复现 → 板上 DNS/证书 → 5s 超时是否太紧 |
| 响应解析失败 | markdown 代码块剥离 → 脏响应容错（P7-05） |
| MQTT 不上报 | Broker 地址/端口 → 低优先级线程是否被饿死 → QoS/重连逻辑 |
| 补传重复 | 队列 seq 去重 → 确认 ack 后才出队 |
